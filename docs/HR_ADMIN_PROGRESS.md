# Статус разработки: кадровый учёт и администрирование

Дата: 2026-09-11. Работы ведутся в изолированной ветке `feature/hr-lifecycle-admin`; работающая версия из `main` не изменена.

## Готово

- HR-карточка расширена безопасными рабочими полями: офис, отдел, должность, статус в отделе, пол, год рождения, дата приёма, распорядок, руководитель и заместитель, СКУД-доступ.
- Миграция `0002_hr_lifecycle_admin` добавляет поля без удаления существующих данных.
- Удаление сотрудника реализовано как архивирование; архивная карточка может быть восстановлена.
- «План» наполняет HR-реестр только один раз. Последующие загрузки плана не меняют кадровые карточки. Для уже заполненной базы создаётся маркер завершённого первичного наполнения без перезаписи данных.
- Есть read-only API карточки для переходов из TimeTrack; сервер запрещает изменение при `source=timetrack`.
- HR-календарь показывает годовщины приёма; HR-аналитика показывает неполные карточки и отделы без заместителя.
- Административные маршруты существуют и закрыты для всех ролей, кроме `admin`.
- Для backup подготовлены выделенный Docker-том `timetrack_postgres_backups`, PostgreSQL client в образе приложения и контракт API с SHA-256.

## Проверено

- HR service/API: 10 тестов проходят после этапа календаря и аналитики.
- Frontend baseline: 33/33 Vitest-тестов проходят в изолированной папке.
- Alembic-маршрут `0001 -> 0002` успешно применён к чистой временной SQLite-базе.
- Контейнер `timetrack-postgres-1` имеет статус `healthy`; в нём доступны `pg_dump` и `pg_restore`.

## Незавершено

- Реальный `backup-service`: создание PostgreSQL-дампа, `pg_restore --list`, SHA-256, каталог backup и запись в журнал эксплуатации.
- Контролируемое восстановление: одноразовая фраза подтверждения, запрет ошибочного подтверждения и аудит до/после операции.
- UI кадрового модуля: полноценная карточка с вкладками, календарь, аналитика, HR-импорт и архив.
- UI администрирования: пользователи/роли, журналы, backup и подтверждение восстановления.
- Реорганизация sidebar: «Кадровый учёт» первым модулем, TimeTrack вторым, «Администрирование» только для admin.
- Встраивание read-only кадровой карточки в таблицы TimeTrack с возвратом по `Esc`.

## Ограничения безопасности

- Не хранятся паспорт, СНИЛС, ИНН, адрес, сканы, фото, личные контакты или произвольные поля.
- Дампы не должны попадать в frontend, `data/`, журналы или API-ответы.
- Восстановление не выполняется автоматически и не доступно HR.
- В браузер не выдаются секреты окружения, строка подключения, содержимое дампа или путь к файлу backup.
