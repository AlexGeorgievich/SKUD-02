# Статус разработки: кадровый учёт и администрирование

Сводка на 2026-09-26. При расхождении с проверенной текущей картой используйте [CURRENT_STATE.md](CURRENT_STATE.md), а результаты — [../TEST_RESULTS.md](../TEST_RESULTS.md).

## Реализовано

- Sidebar разделяет систему на «Кадровый учёт», «Учёт рабочего времени» и «Администрирование»; последний раздел доступен только `admin`.
- HR-модуль содержит вкладки «Сотрудники», «Календарь и юбилеи», «Отчёты и аналитика».
- Реестр поддерживает поиск, фильтры отдела/статуса/испытательного срока, выборку руководителей, архив и создание отдела.
- HR и admin создают, редактируют, архивируют и восстанавливают карточки. Карточка хранит безопасные личные, рабочие, графиковые и СКУД-поля; даты сохраняются в полном формате.
- Демонстрационный КУС заполнен из «Плана» однократно как технологическая операция. Штатная загрузка плана не меняет КУС; HR использует кадровый Excel с preview/apply.
- Из УВР по ФИО открывается read-only карточка. `Esc` и кнопка возврата возвращают в исходное состояние УВР.
- HR-календарь показывает годовщины приёма; аналитика показывает KPI, численность по отделам, стаж и формы работы с drill-down по стажу.
- PostgreSQL backup создаётся только администратором; дамп проверяется и получает SHA-256. Есть двухшаговый API-запрос на восстановление с фразой подтверждения.
- Plan/СКУД/СК проходят отдельный месячный preview/apply с ручным сопоставлением, хранением версий по UUID и экранным расчётом сохранённого результата.
- Изолированный preview `timetrack-preview` на 8001 пересобран, PostgreSQL мигрирован до `0009_uwr_period_history`, `/api/health` и OpenAPI проверены. Для рабочего контура подготовлены `.env.work.example` и `compose.work.yaml` с изоляцией 8002/отдельных томов; контур не запускался.

## Требует пользовательской приёмки или завершения

- Визуальная доводка ширины реестра и строки отделов на целевом разрешении/масштабе браузера.
- UI для управления пользователями и ролями: backend-list пользователей есть, но создание, блокировка, сброс пароля и отзыв сессий через UI не реализованы.
- UI журналов эксплуатации и UI сценарий фактического restore ещё не реализованы.
- Визуальная browser-приёмка адаптивности, HR карточки, месячного импорта и сохранённой аналитики. Browser в текущей сессии недоступен.
- Объединение с `main` допускается только после этой приёмки.

## Безопасность и границы

- Запрещены паспорт, СНИЛС, ИНН, домашний адрес и сканы. Фото и личные контакты ограничены кадровой карточкой и не выдаются списочным API УВР.
- Backup не выдаётся через frontend/API; путь, содержимое и строка подключения не показываются пользователю.
- TimeTrack никогда не получает возможность редактировать HR-карточку, включая роли `admin` и `hr` при входе через УВР.
- Отсутствующая регистрация СКУД остаётся замечанием для проверки, а не кадровой санкцией.
