# Два модуля: кадровый учёт и TimeTrack

> Историческая спецификация от 2026-09-11. Реализация продолжена в `feature/hr-lifecycle-admin`; фактический статус, отличия и незавершённые пункты отражены в [../../CURRENT_STATE.md](../../CURRENT_STATE.md).

## Цель

Превратить текущий минимальный кадровый реестр TimeTrack Pro в самостоятельный модуль «Кадровый учёт», сохранив TimeTrack отдельной системой учёта времени. Кадры ведут безопасные рабочие данные сотрудников; TimeTrack использует личную карточку только для просмотра. В общей системе появляется отдельный модуль администрирования.

## Границы и защита данных

Разрешены только рабочие кадровые и СКУД-атрибуты. Не хранятся паспорт, СНИЛС, ИНН, адрес проживания, сканы документов, фотографии, личные контакты и произвольные поля. PostgreSQL является единственным хранилищем кадровых данных; localStorage и демо-данные прототипа не используются.

## Модули и права

### Кадровый учёт

Это первый модуль в навигации. Он содержит экраны «Сотрудники», «Календарь и события», «Кадровая аналитика» и «Импорт HR». Роли `admin` и `hr` создают, редактируют, архивируют и восстанавливают разрешённые поля карточки; явный HR-импорт доступен тем же ролям. Руководитель видит сотрудников своего отдела, сотрудник — только собственную карточку в режиме просмотра, остальные роли получают область согласно текущей политике доступа.

### TimeTrack

Это отдельный второй модуль: План, Факт, План-факт, Дашборд, За месяц, Проверка данных, По дням, Аналитика и KPI. Он не изменяет кадровые данные. Фамилия сотрудника в таблицах и в модальном окне проверки открывает ту же личную карточку в режиме просмотра. `Esc` закрывает её и возвращает пользователя к предыдущей строке, фильтру и экрану TimeTrack.

### Администрирование

Для роли `admin` появляется отдельный пункт sidebar «Администрирование». В нём доступны: создание, блокировка и архивирование учётных записей; назначение ролей и областей доступа; просмотр журналов входов, действий и эксплуатации; состояние PostgreSQL и Docker-компонентов; создание и проверка резервной копии кадровой БД; восстановление только после явного подтверждения администратора. HR не получает доступ к управлению пользователями, резервным копиям и восстановлению.

## Первичное наполнение и дальнейшее ведение

Первый успешный импорт «Плана» используется один раз для создания кадровой базы: он создаёт пустые карточки с ФИО и отделом из плана. После отметки первичного наполнения новые импорты «Плана» не создают и не обновляют кадровые карточки. Далее только HR ведёт карточки вручную либо выполняет явный «Импорт HR» с preview/apply. Импорт HR изменяет только разрешённые кадровые поля и не подменяет TimeTrack-историю.

Удаление карточки выполняется как архивирование: сотрудник исчезает из активного кадрового реестра, но остаётся связанным с историческими данными TimeTrack, доступен для восстановления HR/admin и имеет запись в аудите. Безвозвратное удаление кадровых записей не входит в интерфейс первой версии.

## Карточка сотрудника

Карточка открывается в полном режиме редактирования только из «Кадрового учёта» и только у `admin`/`hr`. В TimeTrack она всегда read-only. При первоначальном создании ФИО и отдел имеют пометку «Источник: План»; после первичного наполнения их ведёт HR с обязательной записью изменения в аудите.

### Вкладки

1. **Основное:** ФИО из плана, офис, отдел, занимаемая должность, статус в отделе.
2. **Рабочие данные:** пол, год рождения, дата приёма на работу, распорядок.
3. **Структура отдела:** руководитель отдела, заместитель руководителя и срок временного назначения.
4. **СКУД и доступ:** номер и статус карты, уровень доступа, рабочие зоны.
5. **История:** аудит ручных изменений, HR-импортов и синхронизаций из плана.

Допустимые значения статуса в отделе: `Сотрудник`, `Руководитель отдела`, `Заместитель руководителя`, `Временно исполняющий обязанности`.

Все разрешённые HR-поля начинают пустыми после создания карточки из плана. HR заполняет их вручную либо через безопасный HR-импорт.

## Экран «Сотрудники»

Реестр отображает ФИО, офис, отдел, должность, статус в отделе, дату приёма и состояние СКУД. Он поддерживает поиск, фильтры по офису, отделу, статусу и диапазону дат приёма, а также режимы таблицы и карточек. Нажатие на сотрудника открывает кадровую карточку. Плотность таблицы рассчитана на рабочее использование с большим числом сотрудников.

## Календарь и аналитика

Календарь показывает дни рождения по году рождения, годовщины приёма, временные назначения заместителей и окончание таких назначений. Аналитика показывает численность по офисам и отделам, распределение статусов, незаполненные HR-карточки, отделы без заместителя и агрегированные статусы карт СКУД. Отсутствие регистрации СКУД остаётся замечанием TimeTrack, а не кадровым взысканием.

## API и модель данных

Расширяется существующий модуль `backend/app/hr` и его PostgreSQL-таблица `hr_employees`. Добавляются только allowlist-поля: офис, должность, статус в отделе, пол, год рождения, дата приёма, распорядок, связи руководитель/заместитель и даты временного назначения. Существующие поля карты, доступа и зон сохраняются. Для архивирования добавляются состояние карточки, автор и время архивирования. API возвращает различаемые проекции `edit` и `read-only`; сервер, а не UI, запрещает изменения при доступе из TimeTrack или неразрешённой роли.

Административный API отделяется от HR API. Он использует журналируемые операции управления пользователями/ролями, запуск резервного копирования с проверкой дампа, получение списка доступных backup и контролируемое восстановление. В backup не включаются секреты окружения; резервная копия БД получает дату, автора и контрольную сумму.

## Приёмка и тестирование

1. Первичный импорт плана создаёт карточку с ФИО/отделом из плана и пустыми HR-полями.
2. Последующий импорт плана не меняет кадровую базу; явный HR-импорт требует preview и apply.
3. HR редактирует безопасные поля, архивирует и восстанавливает карточку; аудит фиксирует автора, время и изменённые значения.
4. Не-HR получает отказ на API редактирования и импорта.
5. Из всех таблиц TimeTrack сотрудник открывает read-only карточку; `Esc` возвращает к исходному состоянию.
6. Реестр фильтруется по офису, отделу, статусу и дате приёма.
7. Календарь и аналитика используют только разрешённые поля и корректно работают при пустых значениях.
8. Admin управляет учётными записями и ролями, видит журналы и создаёт проверяемый backup без секретов окружения.
9. Восстановление backup требует отдельного подтверждения admin и фиксируется в журнале эксплуатации.
