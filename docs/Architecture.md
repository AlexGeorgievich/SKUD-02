# Архитектура 0.3.0

> В ветке `feature/hr-lifecycle-admin` базовая архитектура УВР расширена PostgreSQL-контуром кадров и администрирования. Текущая функциональная карта: [CURRENT_STATE.md](CURRENT_STATE.md).

## Расширение HR и admin в текущей ветке

| Область | Реализация |
| --- | --- |
| Backend HR | `backend/app/hr/`: SQLAlchemy-модель, репозиторий, сервисы и миграции; маршруты `/api/hr/*` ведут карточки, справочники, фото, календарь, аналитику, архив и HR-импорт/экспорт. |
| Backend admin | `backend/app/admin/` и `/api/admin/*`: список пользователей, создание backup с проверкой и SHA-256, двухшаговый request/confirm для восстановления. |
| Frontend HR | `frontend/src/features/hr/`: реестр, карточка, календарь годовщин и кадровая аналитика. |
| История УВР | `backend/app/uvr/`: PostgreSQL-версии Plan/СКУД/СК и рассчитанные по UUID месячные снимки с точными версиями источников; маршруты `/api/uvr/periods/*`. |
| Read-only УВР | `frontend/src/features/personnel/ReadOnlyEmployeeCard.tsx`: открывается из таблиц УВР, не допускает изменения и возвращает пользователя по `Esc`. |
| Frontend admin | `frontend/src/features/admin/`: пользователи и резервные копии; расширенное управление пользователями, журналы и UI restore пока остаются открытыми. |

КУС является источником списочного состава. Карточки демонстрационных данных были сформированы из «Плана» однократно как технологическая операция; повторные импорты плана не создают и не обновляют КУС. Существующие файловые снимки продолжают обслуживаться legacy-расчётом. Новый месячный контур сохраняет источники по версиям и связывает строки с UUID после preview/ручного разрешения конфликтов.

`UvrService.calculate` объединяет последние версии плана и СКУД по UUID, использует дневной парсер СКУД и добавляет разрешённые числовые показатели последней версии отчёта СК. Сохраняет результат и точные версии входов. Отсутствие регистрации — замечание, не автоматический вывод «прогул». Экран импорта показывает месячную сводку по сотрудникам; текст замечаний СК в эту проекцию не попадает.

Проект — модульный монолит: один Python-процесс обслуживает API и готовый React-интерфейс. Это сохраняет простой локальный запуск и позволяет отдельно менять правила, Excel-форматы и хранение. Микросервисы для текущего объёма не требуются.

## Backend

| Модуль | Ответственность |
| --- | --- |
| `backend/app/main.py` | Фабрика `create_app`, middleware, обработчики ошибок, подключение маршрутов и статики |
| `config.py` | Настройки путей, размера загрузки, допустимых адресов и срока сессии |
| `container.py` | Создание и связывание сервисов и репозитория для экземпляра приложения |
| `api/routes/` | HTTP-вход/выход: авторизация, HR, администрирование, импорт, история УВР и отчёты |
| `api/schemas.py`, `dependencies.py` | Проверка схем и получение зависимостей/текущего пользователя |
| `services/` | Сценарии авторизации, импорта, сверки, просмотра и экспорта |
| `services/ports.py` | Контракт хранилища `Repository` |
| `domain/` | Нормализация ФИ, идентификаторы, календарь, интервалы, роли и ошибки |
| `infrastructure/excel/` | Чтение XLSX, генерация Faker, оформление и запись отчётов |
| `infrastructure/repository.py` | Локальное хранение, шифрование карты ФИ, публикация снимков и журнал |
| `uvr/` | PostgreSQL-версии месячных источников и расчётных результатов |
| `cli.py` | Консольное создание пользователей и генерация пары файлов |
| `backend/tests/` | Проверки правил, полного API-сценария и устойчивости хранения |

HTTP-маршруты вызывают сервисы. Сервисы используют доменные функции, контракт репозитория и конкретные Excel-адаптеры. Домен не импортирует FastAPI, Excel, сервисы или файловое хранилище; это проверяется тестом. Excel-адаптеры пока подключены напрямую: полная инверсия всех зависимостей не заявляется. При появлении второго формата можно ввести отдельный контракт reader/writer.

Фабрика получает `Settings` и при необходимости другой репозиторий. Сессии и ограничения входа принадлежат экземпляру AuthService. Тесты создают независимые приложения во временных каталогах без подмены глобальных путей. Общие изменяемые серверные синглтоны не используются.

## Сохранение результата

Импорт проверяет оба файла и рассчитывает полный результат до публикации. Репозиторий записывает новый каталог `data/snapshots/<id>/` с `result.json` и зашифрованным `identity.enc`. После успешной записи обоих файлов атомарно заменяет указатель `data/current.json`. При ошибке до замены указателя читатели продолжают получать предыдущую согласованную пару.

Используются временные файлы, fsync и os.replace; блокировка действует внутри одного процесса. Это не транзакционная СУБД и не гарантия восстановления после любого отказа диска. Сбой может оставить неактивный каталог снимка. Предыдущие снимки сохраняются, автоматической очистки и UI истории пока нет.

До появления указателя читается старый формат `data/result.json` + `data/identity.enc`. Для обновления нужно перенести всю `data`, включая `secret.key` и пользователей. Для резервного копирования сервер следует остановить. Потеря секрета не исправляется генерацией нового ключа.

## Запуск и расширение

Из корня проекта: `python -m uvicorn backend.app.main:create_app --factory --host 127.0.0.1 --port 8000 --workers 1`. Пользовательский запуск — `start.bat`. `manage.py` оставлен как совместимая оболочка CLI. Зависимости backend закреплены в `backend/requirements.txt`, корневой requirements подключает его.

Данные по умолчанию находятся в корневой `data`; путь можно задать переменной `TIMETRACK_DATA`. При таком запуске создавайте администратора через CLI с той же переменной; start.bat рассчитан на стандартный каталог. Сессии хранятся в памяти и завершаются при перезапуске.

Новое правило сверки добавляется в домен или сервис сверки с проверкой результата на граничном примере. Новый Excel-формат — в Excel-адаптеры. Новое хранилище реализует Repository и подключается в контейнере; перенос на PostgreSQL дополнительно потребует схемы, миграций и проверки транзакций. Новый экран добавляется в features и включается через app. Доступ проверяется сервером независимо от видимости кнопок.

## Проверка

Из корня: `python -m unittest discover -s backend/tests -t . -v`. Из frontend: `npm ci`, `npm run build`, `npm test`. При релизе включать frontend/dist и demo, исключать data, виртуальную среду, node_modules и кеши. Фактические результаты и непроверенные сценарии перечислены в TEST_RESULTS.md.
