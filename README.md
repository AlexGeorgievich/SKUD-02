# TimeTrack Pro — PPL Group

> Для ветки `feature/hr-lifecycle-admin` актуальное описание кадрового учёта, УВР, ролей, запуска и открытых пунктов находится в [docs/CURRENT_STATE.md](docs/CURRENT_STATE.md). Основная ветка `main` эти изменения ещё не содержит.

Локальная тестовая версия 0.3.0 с модульной архитектурой. Интерфейс перенесён на React + TypeScript + Vite; Python/FastAPI и алгоритмы обработки сохранены. Реальный цикл: два XLSX → загрузка мышью → проверка → ETL ФИ → псевдонимизация → сверка → аналитика → Excel с восстановлением имён.

## Быстрый запуск на Windows

1. Установите Python 3.12 или новее с поддержкой `py`. Распакуйте весь архив в обычную папку, например `C:\TimeTrackPro`. Не запускайте из окна ZIP.
2. Дважды нажмите `start.bat`. Первый запуск создаёт `.venv` и скачивает зависимости: для этого нужен интернет. Последующие запуски работают локально без интернета.
3. Для текущей тестовой сборки используйте учётную запись `admin` с паролем `123`.
4. Оставьте окно консоли открытым. Откройте браузер: http://127.0.0.1:8000 . Войдите под `admin` / `123`.
5. Откройте «Загрузка Excel», выберите август 2026. Перетащите `demo/plan.xlsx` в «План работ», а `demo/skud_fact.xlsx` — в «СКУД_факт». Вместо перетаскивания можно нажать выбор файла.
6. Нажмите «Проверить и просмотреть»: ожидается 166 сотрудников в каждом источнике. Затем «Обработать план–факт».
7. Просмотрите дашборд, план, факт, план–факт и «За месяц». Выберите отдел, найдите сотрудника, нажмите его строку, затем «По дням».
8. Нажмите «Экспорт Excel». В книге четыре листа: «План-факт», «За месяц», «Проверка данных», «По дням». Кнопка печати открывает диалог браузера, где можно выбрать принтер или PDF.
9. Для остановки нажмите Ctrl+C в консоли. Данные остаются в `data/`.

Если установка зависимостей прервалась, откройте терминал в папке проекта и выполните `.venv\Scripts\python.exe -m pip install -r requirements.txt`, затем снова `start.bat`. Не открывайте программу для доступа из интернета.

> `admin` / `123` предназначены только для тестирования и отладки локальной версии. Перед продуктивным использованием пароль и порядок управления учётными записями необходимо заменить.

## Дашборд и детализация

Дашборд работает в разрезе всего офиса или выбранного отдела. Фильтр «Отдел» задаёт контекст для всех показателей и позволяет перейти от офиса к отделу, а затем к сотруднику; `Esc` возвращает на предыдущий уровень.

- **Структура офиса по штату** — Treemap: площадь плитки пропорциональна численности отдела. Слева приведён полный список отделов и численность; щелчок по названию или плитке выбирает отдел.
- **Структура плана** — для всего офиса показывает состав статусов по отделам; для выбранного отдела строится Treemap со статусами `О`, `Д`, `Отп`, `Б`, `От`, `Вых`. Легенда находится под диаграммой и содержит цвет, расшифровку и значение.
- **Динамика по дням** сопоставляет плановые дни «О» с наличием регистраций СКУД. **Подтверждение офисных дней** показывает отношение зарегистрированных офисных дней к прошедшим плановым дням «О».
- **Карта замечаний** показывает все календарные дни загруженного месяца. Насыщенность ячейки означает количество записей, требующих проверки. Цветная ячейка открывает модальное окно с исходными строками выбранных отдела и даты: сотрудник, план, факт СКУД, приход, уход, часы и текст замечания. `Esc` или «Закрыть ×» закрывают окно. Отсутствие регистрации не является автоматическим выводом о прогуле.
- **Распределение часов присутствия** отображается для выбранного отдела и группирует сотрудников по суммарным известным часам СКУД за месяц: `0`, `1–80`, `81–120`, `121–160`, `160+`. Это показатель присутствия без вычета перерывов, а не оценка продуктивности или переработки.

## Что изменилось в 0.3.0

- Backend выделен в `backend/`: доменные правила, сервисы, API и адаптеры хранения/Excel. Приложение создаётся фабрикой с явными зависимостями.
- React разделён на `app`, функциональные `features` и общие `shared`.
- Результат и зашифрованная карта ФИ публикуются согласованным снимком через атомарную замену указателя. Старые данные 0.1/0.2 доступны для чтения.
- Запуск Windows сохранён; backend имеет собственные зависимости и тесты.

## Возможности React, сохранённые из 0.2.0

- Отдельные React-компоненты входа, загрузки файлов, таблиц, BI-дашборда и модальных окон сотрудника/расшифровки замечаний. Отрисовка и состояния управляются React; прежний `static/app.js` удалён, это не обёртка над старым DOM-кодом.
- Загрузка через drop и стандартное окно выбора; проверки типа/размера, состояния ожидания и ошибки. Во время импорта заблокированы повторное нажатие, переходы и смена периода.
- Длинные таблицы показывают по 100 строк; поиск и фильтр применяются ко всему набору, а не к текущей странице. Отдельный экран «По дням».
- Экспорт учитывает отдел и строку поиска. В актуальном УВР отдельная кнопка «Без ФИ» убрана; на её месте расположен «Выйти». Аудитор по-прежнему получает псевдонимизированные данные по серверной политике. Кнопка экспорта в окне сотрудника выгружает только его проверку/детализацию.
- Кнопка «Печать» приложения перед открытием диалога печати раскрывает все строки текущей выборки, независимо от страницы. Для этого используйте кнопку приложения; системное Ctrl+P без неё может распечатать только текущую страницу таблицы.
- При истечении сессии рабочее пространство закрывается, доступен повторный вход. Ошибки скачивания показываются в интерфейсе.
- В архив входят исходники React и package-lock.json для воспроизводимой установки, а также готовые JS/CSS-файлы. Внешние CDN и шрифтовые сервисы не используются.

## Разработка интерфейса (не требуется пользователю)

Нужен Node.js 22.12+ или совместимая более новая версия. Из папки `frontend`:

```powershell
npm ci
npm run build
npm test
```

Сборка проверяет TypeScript и обновляет только `frontend/dist/`. Затем запустите Python через `start.bat`. Для непрерывной пересборки используйте `npm run watch`, а приложение открывайте на том же http://127.0.0.1:8000 . Отдельный Vite dev-сервер не нужен: все запросы и cookies остаются на одном origin.

Структура React: `src/app/` собирает рабочее пространство; `src/features/` содержит вход, импорт, таблицы, аналитику и аудит; `src/shared/` — API-клиент, типы, UI и стили. Расчёты и проверка прав выполняются на Python-сервере. Подробности — в `docs/Architecture.md`.

## Переход с 0.1.0 или 0.2.0

Остановите старый сервер и сделайте резервную копию его папки. Распакуйте 0.3.0 отдельно. Если необходимо сохранить пользователей и последний результат, скопируйте **всю** старую папку `data/` в новую `timetrack/data/`, включая secret.key и identity.enc. Не переносите только один файл ключа или карты. Старую `.venv` копировать не нужно. Запустите новую сборку. Старый ZIP остаётся отдельной резервной версией. Одновременные запуски на порту 8000 невозможны.

## Входные данные

Готовый набор: август 2026, 31 день, 17 отделов, **166 сотрудников**. Отделы и численность взяты из задания без исправления написаний `Accounting Offiline` и `Finace`. Faker ru_RU, seed=42. Уникальные базовые ФИ; в СКУД внесены изменения регистра и пробелов. Есть дни без регистрации и неполные пары. Случайные совпадения с реальными людьми возможны, реальные кадровые данные не использовались.

План: период в B2, заголовок в строке 4, далее «Отдел», «Сотрудник», календарные дни. Отделы объединены вертикально, надписи повёрнуты на 90°. Статусы: О, Д, Отп, Б, От, Вых. СКУД: период в B2, заголовок в строке 9, далее №, Ф И, дни, итог месяца. Сотрудники отсортированы по фамилии. В ячейке четыре строки: приход, уход, `--`, длительность. Подвал содержит суммы. Суммы свыше 24 часов отображаются форматом `[h]:mm`.

Для другого месяца используйте кнопку скачивания тестовой пары в интерфейсе или:

```powershell
.venv\Scripts\python.exe manage.py generate --period 2024-02 --out demo_february
```

Календарь учитывает длину месяца и високосность. 5/2 означает понедельник–пятницу; государственные праздники, переносы и сокращённые дни пока не включены. Для проверки месячных итогов удобнее выбирать завершённый месяц.

## Правила обработки

1. Проверяется расширение XLSX, размер до 20 МБ, распакованный размер до 80 МБ, до 3000 строк/80 колонок, заголовки, B2 и последовательность дней.
2. ETL идентификации применяется только к ФИ: Unicode NFKC, пробельные символы, регистр. Исходное имя плана сохраняется для восстановления. Отдел — атрибут ключевого плана, не дополнительный признак сопоставления.
3. Е/ё, похожие латинские буквы, опечатки и перестановки слов не объединяются автоматически. Инициалы и отчество требуют уточнения. Дубли нормализованных ФИ останавливают весь импорт, а не выбираются «по первой строке».
4. HMAC-SHA-256 с локальным секретом создаёт стабильный ключ. После сопоставления расчётные данные содержат идентификатор, а не имя. При смене секрета меняются идентификаторы; не удаляйте `secret.key`.
5. Объединение выполняется от плана: все 166 сотрудников остаются, даже если записи СКУД нет. Лишние ФИ факта учитываются отдельно как несопоставленные технические идентификаторы.
6. Минуты рассчитываются как уход минус приход. Указанный итог дня сравнивается с этой разницей; несовпадение помечается. Неполная пара не превращается в 0 часов — число часов недоступно. Месячный итог источника не является источником расчёта; сверка его с пересчитанной суммой — следующий этап.
7. Перерыв не вычитается: показатель называется «часы присутствия СКУД», а не «отработано». Ночные переходы суток требуют уточнения. Внутридневные повторные входы/выходы не поддержаны этим агрегированным шаблоном.
8. Отсутствие регистрации при О — замечание для проверки, не доказанный прогул. При Д отсутствие прохода не считается нарушением. Будущие дни не считаются неявками. KPI подтверждения офисных дней: прошедшие дни О с хотя бы одной регистрацией / все прошедшие дни О. Неполная регистрация входит в числитель, но одновременно отмечается как проблема. При нулевом знаменателе KPI недоступен.
9. Отчётные числа — рассчитанные снимки, не Excel-модель с пересчётом формул при ручном изменении. Для пересчёта измените входные файлы и повторите импорт.

## Защита и роли

Это **псевдонимизация**, а не необратимая анонимизация. График, отдел и длительности могут косвенно идентифицировать человека. В `data/snapshots/<id>/result.json` нет ФИ. Карта восстановления хранится рядом отдельным файлом `identity.enc`, зашифрованным Fernet. `data/current.json` указывает на активный согласованный снимок. Старые файлы `data/result.json` и `data/identity.enc` читаются для совместимости до первого нового импорта. Секрет — `data/secret.key`; учётные записи с PBKDF2-хешами — `data/users.json`. В архив не включены секреты, пароли или реальные исходные таблицы.

Секрет и шифротекст находятся на одном компьютере: это не защищает от администратора ОС или копирования всей папки. Доступ к `data/` необходимо ограничить средствами ОС. В продуктивной версии нужен отдельный защищённый контур ключей. Оригинальные файлы не сохраняются сервером; пользователь хранит их самостоятельно.

| Роль (код) | Доступ |
| --- | --- |
| Системный администратор (`admin`) | Все записи, импорт, экспорт с ФИ, журнал |
| Администратор табельного учёта (`timekeeper`) | Все записи, импорт, экспорт с ФИ |
| HR (`hr`) | Все записи, импорт, экспорт с ФИ |
| Руководитель (`manager`) | Только закреплённый отдел, просмотр и экспорт |
| Топ-менеджер (`executive`) | Все записи, просмотр и экспорт |
| Сотрудник (`employee`) | Только собственная запись, просмотр и экспорт |
| Аудитор (`auditor`) | Все записи без ФИ, экспорт псевдонимов, журнал; без импорта |

Права применяются на сервере и при выгрузке, а не только скрывают кнопки. Создание пользователей пока выполняется из консоли:

```powershell
.venv\Scripts\python.exe manage.py user hr_user --role hr
.venv\Scripts\python.exe manage.py user head_hr --role manager --department "HR"
.venv\Scripts\python.exe manage.py user employee1 --role employee --employee "Фамилия Имя"
.venv\Scripts\python.exe manage.py user auditor1 --role auditor
```

Для сотрудника укажите точное ФИ из плана. Ключи соответствуют только данной установке. После входа назначенные права действуют до завершения сессии (8 часов). Сессии в памяти: перезапуск завершает их. Вход, импорт и экспорт фиксируются в журнале, который пока не защищён от изменения владельцем файлов. Выход прекращает сессию; отдельной записи о выходе пока нет.

## Ограничения версии

- Это тестовый вертикальный срез, не промышленная HR-система. Для проверки используйте синтетические файлы.
- Тестовый шаблон поддерживается строго. Ранее приложенные исторические книги с другой шапкой, несколькими месяцами и неполными календарями ещё не импортируются.
- Интерфейс показывает один активный набор; повторный импорт публикует новый снимок. Предыдущие снимки остаются на диске, но интерфейса истории и автоматической очистки пока нет. Работайте одним оператором с одним серверным процессом; межпроцессная синхронизация и несколько организаций не поддержаны.
- Нет редактирования графиков, ручного разрешения конфликтов, отпускных согласований, штатного Т-13, KPI продуктивности, интеграции почты/СКУД/1С.
- Windows-установщик EXE и зависимости для полностью офлайн-первой установки в архив не входят. Первый запуск требует скачивания Python-пакетов.
- Восстановленные Excel содержат имена. Раздавайте их только уполномоченным пользователям.

## Кадровый учёт (первый этап)

Кадровый контур включается через PostgreSQL в Docker Compose. Скопируйте `.env.example` в `.env`, задайте локальный пароль и запустите:

```powershell
docker compose up -d --build
```

Сервисы `postgres`, `migrate` и `app` используют именованный volume `timetrack_postgres_data`; `docker compose down` сохраняет кадровые записи, а `down -v` удаляет volume. Первый импорт «Плана» формирует кадровую базу; далее HR ведёт карточки вручную или через безопасный HR-импорт preview/apply. В меню «Кадровый учёт» доступны реестр, карточка с вкладками, календарь юбилеев и аналитика. Изменять кадровые поля могут только роли `admin` и `hr`; паспорт, СНИЛС, ИНН, адреса и сканы намеренно не поддерживаются. Переход из УВР по ФИО всегда открывает ту же карточку только для просмотра.
